# 山西负荷预测竞赛

---

## 1. 背景

### 什么是电力交易

2015年以前，中国电力行业实行计划体制：政府统一定价，电网统购统销，发电企业和用电企业都没有自主定价的空间。2015年，国家推动电力市场化改革，电价开始根据市场供需实时波动。

改革之后，发电侧和用电侧都需要主动参与市场，根据价格信号买卖电量。**电力交易员**这一岗位由此诞生——他们的核心职责，是在价格波动中为企业寻找最优的买电策略，降低用电成本。

### 交易窗口

用电企业的交易员需要提前规划每一天的用电，在不同时间窗口分批买卖电量。

**中长期窗口**（前一年 / 季度 / 月 / 周）
企业提前预估用电需求，分批采购。通常八九成的电量都在这个阶段锁定，价格相对稳定可预期。

**日滚动窗口**（周内）
根据需求变化和市场价格，在已购电量的基础上微调。需求增加则补买，需求减少则卖出。部分交易员会在此阶段进行套利操作：价格低时超买，价格高时超卖，赚取价差。

**日前申报窗口**（D-1 日）
这是最后一道关口，也是本项目聚焦的核心场景。

### 日前申报

实际用电当天称为**出清日（D 日）**。在 D-1 日，交易员手中通常还有 10%～20% 的电量尚未购买，需要决定是否在日前市场完成购买。

这里有两种价格：**日前价格**（D-1 日买入，价格在申报时锁定）和**实时价格**（D 日电网自动平仓，按实际用电量结算）。

交易员的决策逻辑如下：

- 若判断**日前价格高于实时价格** → 空仓，等待 D 日实时自动平仓
- 若判断**实时价格高于日前价格** → 日前满仓，避免在 D 日以高价被动买入；甚至可以超买，在实时平仓时反向卖出套利

**申报格式**：D 日被划分为 **96 个时段**，每个时段 15 分钟。交易员需逐一填写每个时段的预计用电量，汇总成表格提交给交易中心。

**申报的考核压力**：交易中心要求提交的申报电量与实际用电量的偏差，每小时控制在 **10% 以内**，超出则触发考核（罚款）。申报不准确还会直接影响用电成本——若预测严重偏低，大量电量将被迫以实时高价补入。

### 建模之外的问题

这是一个真实的工业项目，有大量无法用模型直接处理的问题。解决这些"模型外"问题的经验，往往才是老手和新手之间最大的差距。以下是我们在实践中积累的部分经验，供参考：

**① 计量表计的振荡问题**
许多用电户的用电曲线呈现周期性振荡，看上去像噪声。这并非真实的用电规律，而是旧款计量表计采集频率不足（半小时或一小时一次）造成的数据失真。电网以这份数据作为结算依据，且振荡相位有时会发生漂移。

**② 数据质量问题**
交易中心的数据并不可靠，缺漏和异常值时有发生。

**③ 用电行为的动态变化**
用户的用电情况持续变化。季节、天气、生产订单、设备检修、节假日，都会显著改变用电曲线的形态。不同行业、不同规模的企业，用电模式也差异显著。

### 工业界项目与课堂项目的本质区别

**课堂项目**是考试题：有标准答案，有唯一的评分标准，问题本身是有解的。

**科研项目**是在理想条件下对单一指标的极致优化，就像在真空中研究羽毛和铅球的自由落体——追求揭示最根本的规律。

**工业界项目**则是在有限时间、有限成本、复杂多变的真实环境中，寻找一个局部最优解。没有唯一答案，没有统一标准，只有在生存压力下的权衡与妥协。

这就是为什么在工业界，我们从来不建议过度纠结于技术本身。就像士兵：只有没上过战场的新兵，才会强调自己的剑术；而老兵只会说一句话：

> *I am a survivor.*

**所以，在这个项目里：try everything you can to survive。**

## 2. 任务目标

基于历史用电数据，预测 **D 日**全天 **96 个时段**（每段15分钟）的用电量。

评估指标为 **MAPE（平均绝对百分比误差）**，MAPE 越低，预测越准确。回测范围为 **2026年2月1日至3月31日**。

---

## 3. 数据说明

### 数据可用性约束

交易中心发布的历史数据存在**约 5 天的延迟**。在 D-1 日申报时，可用的最新实际数据只有 **D-6 日及更早**的记录。

| 日期 | 说明 | 数据是否可用 |
|---|---|---|
| D 日 | 出清日（预测目标） | ❌ 未来 |
| D-1 日 | 申报日（今天） | ❌ 未发布 |
| D-2 ～ D-5 日 | 近期历史 | ❌ 未发布 |
| **D-6 日** | **最新可用数据** | ✅ 可用 |
| D-7 日及以前 | 更早历史数据 | ✅ 可用 |

### 基础数据：`total_consumption.csv`（必用）

每15分钟一条记录，包含两列：

| 列名 | 说明 |
|---|---|
| `timestamp` | 时间戳 |
| `consumption` | 该时段总用电量（MWh） |

### 扩展数据：`by_meter.csv`（选用）

将总用电量分解到每一块电表的原始记录：

| 列名 | 说明 |
|---|---|
| `cons_no` | 客户 ID |
| `measure_id` | 电表 ID |
| `info_date` | 日期 |
| `info_time` | 时间字符串（如 `00:00`、`00:15`） |
| `value` | 该时段该电表的用电量 |

## 6. 参赛规则

### ✅ 可以修改

`model.py` 里的所有内容，包括：

- import（引入任何第三方库）
- 缺失值填补逻辑（`fill_missing`）
- 特征工程（`build_train_features`、`build_predict_features`）
- 模型选择与超参数（`get_model`）

### ❌ 不可修改

`src/` 目录下的所有文件，以及 `run.ipynb`。这些文件保证所有人在相同条件下被评分。

### ⚠️ 避免 Data Leakage

Data leakage 指在构造特征时，无意中使用了在真实预测场景下不可能获取到的数据，导致模型在回测中表现虚高，但在真实环境中完全失效。

在本项目中，预测 D 日用电量时，你只能使用 **D-6 日及更早**的数据。以下行为均属于 data leakage，必须避免：

- 使用 D-1 ～ D-5 日的实际用电数据构造特征
- 使用 D 日当天的任何信息

本地回测通过不代表真实有效。后续我们会将代码打包成 Docker，在真实环境下进一步验证。

## 7. Baseline

示例代码使用 `HistGradientBoostingRegressor`，特征如下：

| 特征 | 含义 |
|---|---|
| `slot` | 当天第几个时段（0～95） |
| `dayofweek` | 星期几 |
| `lag_nd` | D-6 日同时段用电量（最新可用数据） |
| `lag_nd1` | D-7 日同时段用电量 |
| `lag_7d` | D-7 日同时段用电量（上周同日） |
| `lag_14d` | D-14 日同时段用电量（两周前同日） |

在 2026年2月～3月的回测中，baseline MAPE 为 **22.76%**。

## 8. Extra Point（进阶挑战）

`data/by_meter.csv` 包含每个用户的独立用电量记录。

一种可能的思路是对每个用户单独建模预测，再将各用户预测值求和得到总负荷预测。这一方向完全在现有框架内实现，最终输出仍为汇总后的 `predicted` 列，接口不变。

是否真的比直接预测总负荷更好？欢迎探索。
